# 产品需求与决策记录（2026-11-16）

本文记录项目方向，跨会话有效；更改需有明确提交记录。是**需求而非已实现清单**。

## 用户体验目标

- 想要“真正理解我和我的游戏账号”的私人 AI，而不是 OCR 匹配界面后依靠固定坐标/脚本操作。
- AI 应识别已有角色、光锥、遗器、培养程度以及喜欢的角色和资源约束；解释为何使用某套阵容/配装，知道自己缺哪些数据。
- 优先解决自动配队、遗器评估和装备建议、模拟宇宙、末日幻影，再研究对战局变化作实时决策。
- 战斗分析应把目标、技能点、终结技、敌人机制、进度及失败原因作为决策依据。**不会声称现有助手已经具备这些能力**。
- 继续保留三月七小助手成熟的日常自动化，不因此牺牲稳定性。
- 能和 AI 自然语言交流，按需解释操作，并能中止自动操作。

## 移动端体验

- 起点设备：iQOO Pad5 Pro、OriginOS、Shizuku 授权；用户没有电脑且不想手动写代码。
- 当前每次启动任务自动创建虚拟屏，体验不好；新需求为选择前台实体屏，保留后台虚拟屏作为另一个模式，研究服务会话复用（不等于承诺永不新建）。
- 优先自动识别真实账号，不能要求用户每次重复大量手动输入。
- **更新决策（2026-11-17）**：用户优先要“像录屏一样让 AI 看见正在进行的游戏”，而不是先 OCR 再由 AI 分析文本；**OCR 由必经流程降为可选工具**。Android 和 Windows 共用实时视觉决策核心；本地可连续采集，但默认**不连续上传云端视频**，关键场景才经用户授权把帧/短视频交给视觉模型。支持暂停上传和严格预算。

## AI 接入

- GPT 可以；同时允许 DeepSeek、通义千问、OpenAI API、其他兼容服务。
- ChatGPT OAuth 为独立功能目标：按官方当时文档和实际权限验证，不与通用 OpenAI API Key 混淆，不绕过授权/计费限制。
- 文本/多模态/动作规划分别验证，不根据模型品牌假设有视觉功能。
- 用户使用同一个账号档案于 Windows 和 Android；跨设备同步属于后续可选能力，默认不把隐私数据公开存储。

## 平台

- 目标不是只做 APK：Windows + Android 双平台核心，macOS/Linux 按可行性逐步适配，iOS/iPadOS 先顾问。
- 优先研究 PC 原代码的正确行为与适配条件，再移植移动端；不要简单复制运行不兼容的 PC 自动战斗脚本。

## 用户无需做的事

- 不要求持有 PC / 安装 Android Studio / 执行 Git 命令。
- 代码、测试、构建配置由开发者维护在 GitHub；用户主要通过平板安装产物、反馈问题、授权 AI 账号与必要的截图。
- 不要求在公开 GitHub Issues 中发送个人账号、游戏截图或 API Key。

## 交付标准

- 公开说明“已经实现”和“拟实现”的差异，能验证则附 commit、CI、实际 APK 链接。
- 不得在未经设备实测前宣传 Shizuku 前台操控/高难关卡为可用。
- 模型行动受白名单和风险确认约束；有停止按钮与观察结果反馈。
