# 低 Token 运行策略（架构要求，尚未全部实现）

本文件记录用户明确提出的成本顾虑：**不得以“每步截图 → 云端 GPT 判断 → 点击 → 再截图”的无限循环作为默认运行模式**。AI 需要理解账号和游戏，但不能靠无节制地上传视觉数据消耗额度。本策略对 Windows/Android 公共 AI Core 生效。

## 1. 默认路径：本地优先

1. `FrameSource` 可持续在本地内存中获取游戏画面流；本地缩略帧差异、场景变化检测、窗口焦点与状态验证优先端侧执行；**不要求先 OCR**。OCR 仅用于局部数值校验等可选能力。**本地计算不消耗云模型 Token**，但仍有耗电/CPU 成本。
2. 本地画面流和上传渠道分离。选中的关键帧/短片段可直接交给视觉语言模型做场景理解，**无需中间 OCR 文字化**；模型结果只缓存紧凑结构化状态（角色/敌人/技能点/阶段/信心分数、时间戳），不把每一帧都上传或塞进上下文。
3. 已验证的低风险日常操作走本地状态机及 `ActionGuard`；只有出现新机制、复杂配队、状态歧义、失败复盘或用户显式提问才调用云 AI。
4. 遇到识别失败时，先利用本地帧缓存/变化检测，必要时使用本地 OCR 或轻量视觉模型；**用户需明确开启云视觉上传权限**，只传本次必要的裁剪关键帧或可控短视频，默认云上传关闭。
5. AI 返回高层计划，由本地动作校验器执行，每个动作执行后本地验证。**不能把连续操作的每一帧自动送去云端**。
6. 已验证策略按版本、关卡、账号摘要、敌人配置、有效期缓存；关键机制版本变化或置信度不足才重新求解。不得把旧战斗数据无条件复用。

## 2. 预算与可见控制

- **默认不开启自动上传截图**。用户必须明确选择上传给哪个 Provider，并看到上传对象类型。
- 第一次实现自动云决策时，必须提供**每任务最大云调用次数、最短冷却时间、可配置的每日/每场预算上限**；到达上限须停止云调用或切换至安全的本地已验证流程，绝不能自动超预算。
- 模型调用要记录非敏感指标：Provider、模型、请求类型（文本/视觉）、调用次数、返回的 usage（如提供）、成功/失败、粗略费用估算。**不记录 Token、API Key、游戏截图或隐私账号原文**。
- 针对异常画面，必须做帧去重、过期检查、裁剪与降分辨率（在不破坏识别的前提下）；不能连续上传相同画面。
- 策略规划可选低成本模型→高能力模型逐级升级，但升级次数也需预算限额。
- OCR 不是永远准确，遇到关键状态不确定时宁可中断/请求用户协助，不通过密集云调用赌结果。
- 在 OAuth 模式下也要限制请求：即使使用的是 ChatGPT 方案额度，也可能有速度和使用量限制，不能假定“免费无限”。

## 3. 阶段验收（所有条目仍待实现）

- [ ] 模拟 1,000 帧重复画面，默认**零次**云端视觉上传。
- [ ] 稳定已知日常流程默认不因每次 OCR 帧触发云模型调用。
- [ ] 多轮战斗的模型请求由事件触发，提供可追溯但隐私安全的调用计数。
- [ ] 同一局面重复识别优先使用有效策略缓存，关键状态变化能正确使缓存失效。
- [ ] 达到用户设置的次数或预算上限立即停止云调用，并报告原因。
- [ ] 用户关闭上传权限后不再发任何截图，且保留“立即停止”。
- [ ] 在 iQOO Pad5 Pro / OriginOS 与 Windows 上记录本地帧采集、差异检测、可选 OCR、视觉模型延迟、耗电和网络失败的安全停止行为。
- [ ] 视觉模型直接看图的通路不需要 OCR；支持视觉帧的 Provider 才可选择该通路，视频/帧输入都计入模型调用预算。

**当前仓库已实现的 AI 顾问是用户主动点击发送文本；尚未提供自动视觉云上传、事件型智能战斗和预算计数器。以上是强制开发要求，不是已经完成的功能。**
