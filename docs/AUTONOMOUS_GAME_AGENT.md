# StarRail-AI 自主游戏智能体：AI 主驾驶，不是任务启动器

> 产品定位修订（2026-11-17）：**最终目标是让 AI 在用户明确授权后，尽可能独立地玩《崩坏：星穹铁道》。** 三月七小助手的固定脚本和任务系统是可选择的高效工具，不是 AI 能力的上限。本文是工程目标；**目前没有完整视觉接管、执行或自我纠错的可运行闭环**。

## 一句话定义

**AI 始终拥有任务目标与规划权，任何固定自动化只是它可调用的技能；技能失败时，AI 可以在确认游戏状态并取得独占输入权之后，接管当前画面继续完成目标，并通过画面反馈验证效果。**

这比“AI 一句话启动 daily / currencywars，然后等失败报告”更进一步。

## 两种平级入口

1. **AI 直接游戏模式（Agent-first）**：用户说“自己去刷材料、查看练度、安排配队”。Agent 观察当前游戏、读取可靠的账号数据、决定目标和步骤，再从可用工具中选择直接控制或调用成熟自动化子任务。
2. **脚本自动化模式 / AI 接管回退**：AI 认为 `currencywars` 或 `power` 等任务成熟时，发起 M7A 任务。若脚本不认识当前画面、卡住、误判、缺少素材、网络失败或输出前后矛盾，Agent 可申请独占接管，直接理解当前游戏画面并尝试恢复。修复成功后，决定恢复脚本或继续自主操作。

**不要求所有动作先经过三月七小助手；也不能在它失效后仅依赖报错文本猜测当前局面。**

### 自主发现和脚本失效的具体处理

以货币战争更新后出现不认识的活动弹窗为例：

1. 本地监督器发现 M7A 连续无法识别场景、任务重复/超时，或动作执行后预期状态未出现。优先使用已有异常日志与局部画面，不能把“脚本报错”直接当作用户授权。
2. **通知 M7A 暂停并获取输入释放确认**。没有独占输入权则不能让 Agent 并发点击。
3. 通过 MediaProjection / Shizuku / Windows 捕获真实当前帧，由视觉模型直接理解弹窗（**无须先 OCR**；精确数字可补 OCR）。AI 必须陈述不确定信息。
4. Agent 按当前目标拟定少量、可验证的高层动作（如关闭非必要弹窗、返回任务棋盘、重新选择可见目标），逐步执行并回看新画面；不能运行任意 Shell 或自动改游戏文件。
5. 若进入原版脚本能处理的场景，**只有核对状态**才将输入权交还给 M7A；否则 Agent 可以继续进行在权限范围内的自主步骤。
6. 反复失败、敌方 UI 已改变导致定位不可靠、离开游戏、超预算、权限撤销等情况一律暂停/退出，交由用户处理。不能无限重试。
7. 仅将经过成功验证的动作/场景转移作为**带版本和设备条件的候选经验**存入本地；若要修改共享自动化代码，需要独立测试与审查，不能在失败现场由模型直接编辑生产脚本并执行。

### 自主范围

目标包括账号与背包观察、资源规划、日常、货币战争、模拟宇宙、高难关卡、配队、战斗技能与策略执行。具体可用度要按玩法和平台逐项验证；不能因“最终目标几乎全接管”就声称支持所有玩法。

AI 并不是无限授权的机器人。用户需要授权游戏范围和任务目标，保留可见停止/接管开关。抽卡、消费星琼/付费货币、购买、遗器销毁、不可逆道具使用、账号修改等高风险动作，要经过真实的用户确认，不能让视觉模型仅靠文本自行确认。要考虑游戏自动化可能产生的账号与服务条款风险。

## 技术分层

- **游戏观察（未实现）**：Android 实体屏本地帧流 / 可选后台虚拟屏；Windows 窗口视频帧；UIA/Accessibility 只补系统控件，不假定能读取游戏 HUD。
- **游戏场景模型（部分基础）**：`data/game_scenes.json` 已提供 PC/触屏导航图，但还不是实时场景感知或玩法知识；需要 VLM 与视觉定位支持。
- **工具调用（原版上游已提供 PC 工具；本站未接 AI 编排）**：M7A 命令行、任务/Skill、日志、回收状态；安卓后台已有有限任务，触屏不支持 PC 的全部高难玩法。
- **Agent Planner（未实现）**：基于任务目标、游戏状态和可用工具做动态规划；缺陷调查、适配未知场景、重计划；需要支持模型策略与本地确定性备选。
- **输入权和接管安全契约（Python 原型）**：`starrail_core/agent_handoff.py` 提供单会话的 `AgentHandoff`，脚本暂停确认、授权与焦点/新鲜帧验证、短时 Agent 租约、动作风险检查及恢复交接状态；**它不采集屏幕、不调用 AI、不发触摸/鼠标，运行环境无法单凭此文件证明脚本已实际暂停**。平台执行器必须额外实现可信输入锁和实际焦点/目标检查。
- **Live Vision 费用闸（Python 原型）**：`starrail_core/live_vision.py` 默认拒绝云截图上传，有限额与冷却；需与实际 FrameSource 和支持视觉输入的 Provider 接通。
- **经验库（未实现）**：任务效果、场景版本、失败类型与已验证恢复动作；用户可清除，切忌将过时点击路径当万能规则。

## 核心约束：自主但不盲目

AI 可以自主决定“想做什么、使用哪个工具、怎样绕开失效的固定流程”，但 **`模型建议` != `具备执行权限`**。每个真实动作必须同时满足：用户对任务/场景的许可、当前仍在目标游戏、帧/定位新鲜、输入权独占、动作目标有证据、风险在允许范围内、以及执行后可验证。任务级授权可以覆盖大量低风险可逆操作，不必每次点触都询问；高风险不可逆操作仍需确认。

对未知操作，Agent 应先小步试探，检验新画面和目标进度；不要擅自解除安全锁来“提升成功率”。

## 可验收路线（优先级从高到低）

1. **输入权契约（Python 原型）**：先测试 AI-first、脚本失败后暂停/接管、复位、租约过期、错误焦点/过期帧/高风险动作拒绝。CI 通过仅证明逻辑，不是设备接管。
2. **安卓实体屏只读捕获**：在用户授权的 iQOO Pad5 Pro/OriginOS 前台游戏连续采集本地帧；Windows 做对等驱动，并提供失焦/切应用自动停止。
3. **真实的模型场景理解**：模型能返回游戏是什么、当前场景、可执行目标与不确定性；用官方场景图和 AI 视觉互相校验，未知不猜。
4. **AI-first 受限实控**：先通过 UI 入口导航、打开/关闭已验证按钮，在真机及 PC 反复确认安全；能够动态选择是否调用 M7A 子任务。
5. **M7A 工具→AI 故障接管实测**：有可控故障的样本与场景变化，证明输入互斥、Agent 查明失败原因、恢复后可选择交还脚本，不成功能安全中止。
6. **玩法扩展**：从日常和货币战争逐步扩充到角色面板/培养、高难和回合战斗决策；持续记录任务成功率、误操作、耗电、延迟和 Token。
7. **经验复用**：同一可靠场景无需重复全量云视觉；对未验证新 UI 保持视觉回退。

## 接入 ChatGPT

现有安卓 ChatGPT OAuth 是未经真机验证的实验性接入，并不能证明具备“实时视频 + 持续 tool calling + 本机输入执行”。需验证实际可用模型、授权、视觉接口与费用限制；没有连接 GPT 时可先开发和测试本地捕获、策略、输入锁和模拟恢复。

结论：**StarRail-AI = 游戏智能体主体；M7A = 技能工具箱；Live Vision = 眼睛；受限执行器 = 手；验证/经验 = 反馈和学习。**
