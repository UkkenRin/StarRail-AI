# Android Shizuku AI 原生游戏控制：首个受限单步实验

> 2026-11-17。此次实现**不是 Gamer 已经能连续玩星铁**，也不是通用模型的任意点击能力。保留 M7A GPL 来源与上游服务协议。

## 真实接通哪些层

1. Android「AI 顾问」页可请求从 M7A `DeviceAccess` 打开一条**独立 Shizuku 授权会话**；不启动 M7A 脚本、不创建虚拟屏、不重新启动游戏、不修改音量、屏幕电源或焦点。并发 M7A 任务或服务已被占用会拒绝。
2. 向原版 DeviceService 发送带随机 token 的 `hello`，启动**只监控、没有自动回迁/对焦/重启**的 `watchdog`（`display_id=0`），轮询 `status` 检查任务顶层 Activity、显示器、时间戳、锁屏和可见状态；默认提供“5 秒后检查”只读入口，便于用户切到星铁再检查。
3. 第二个必须**单独弹窗同意**的实验入口，限定唯一低风险操作：**星铁主界面 → 打开手机菜单**。要求在安卓实体屏 MediaProjection 会话中保留的真实画面足够新鲜且持续采集、Usage Access 最近前台提示为星铁、共享内容可见；同时 DeviceService 看门狗确认星铁主 Activity 在 display0 上可见且状态新鲜。
4. `SafeGameMenuDetector` 直接从 APK 内打包的固定上游 `project.zip` 加载 M7A touch_720 的 `main.png` 模板，在**本机真实最新画面的约定位置**做高阈值相关性匹配。没有匹配则拒绝操作；**模型不能输入坐标**。当前仅支持同 M7A 720p UI 的 16:9 画面几何，iQOO 原生 16:10 / 分辨率不适配时直接拒绝，不猜测缩放。
5. 操作前重新获取 `status` 和原始采集会话，核对 **display0 逻辑像素尺寸**等于投影整个屏幕的尺寸，拒绝单应用裁剪、黑屏、离线帧或尺寸不匹配。坐标固定为上游 `main -> menu` 已知左上角安全按钮（来自固定版本 `screens.json`，不是模型生成）。
6. 通过 M7A `DeviceService.tap(display_id=0)` 执行最多一次 50ms 轻触。设备服务开启显示器 0 的看门狗后，底层还要求游戏 UID 定向输入；如果 Android/OriginOS 不支持 UID 定向注入会**直接拒绝**，不退化到任意系统触控。
7. 点击后观察同一录屏会话的新画面，并尝试用本地 `menu.png` 模板确认手机菜单。未确认即返回 `unverified`、不重复点击、**不记录成功经验**。通知栏或应用页面停止共享会中断进一步检查。

## 还缺什么

- **Android 真机验证**：窗口真实焦点与 UID 注入能力、OriginOS 保活、模板的实际画面匹配率、物理屏是否是 16:9、系统截图权限续期。任务可见仅是候选，仍不是“绝对焦点证明”；本次入口依靠目标 UID 定向及多重本地检查来限制风险。
- **AI-first 主运行器进入 Android**：现有 `starrail_core/gamer_runtime.py` 的 Python ModelPort / TrustedGamePort 仍未与这个 Kotlin 单步连接；现在是用户主动批准的固定测试动作，而**不是 AI 选择动作后的全自动执行**。
- Gamer 的连续动作、动态坐标、其他触控目标、持续背景任务、真正长期记忆持久化、取消点击后的回滚、完整目标验证仍待实现。
- 还须核对玩家是否愿意承受游戏自动化的账号条款风险；程序无法承诺不会封号。

## 平板测试（只在新 APK 通过 CI 且用户愿意时）

1. 先在 AI 顾问启动本机观察，系统共享区域选择**整个屏幕**；检查预览确实是星铁。使用情况访问的前台诊断权限仅供进一步谨慎检查。
2. 授权 Shizuku，并确保没有同时运行 M7A 常规任务。
3. 可以先点击「5 秒后只读检查星铁状态」，切换到星铁并保持在主界面；返回 App 看设备探测结果。
4. 只有确实希望测试点击时，明确选择「准备测试 AI 设备执行器（打开菜单一次）」，阅读二次弹窗。确认后立刻切到星铁主界面，直到操作完毕。
5. 记录结果：`blocked`（没有触摸）、`unverified`（触摸已发送但无法确认菜单）、`verified`（新画面检测到菜单）。不要公开分享截图、OAuth Token、Shizuku token 或个人账号信息。

开发原则：**M7A 是复用的设备能力与可选技能，并不是 AI 的决策层。** 这轮是给 AI-first 运行器建立真实 Android 数据与输入底座，严格区分执行器、模型及真机实测。
